影片文件一多，问题就从「存不存得下」变成「找不找得到」。同一部片子在不同硬盘各留一份，分卷和不同版本混在同一个目录，文件名是复制来的乱码，换一台机器就不知道上次看到哪儿。拿文件夹和文件名当数据库，规模一大就撑不住了。

**Peach** 是一个本地优先的影片元数据刮削与馆藏管理器。它把散落在本地硬盘、SMB 共享和网盘里的影片扫成一个统一馆藏，补上标题、演员、厂牌和封面，再用浏览器以海报墙的方式浏览和播放。项目 2026 年 8 月开源，AGPL-3.0 许可证，到 11 月 21 日累计约 1.5 万星。

> 本文依据项目 README、官方文档（含 170 余条架构决策记录）、发布清单与公开仓库数据整理，属资料型使用评价，未对全部功能逐项实机测试。功能状态以官方仓库为准。

## 一、核心功能

### 1. 本地盘、SMB 与网盘汇成一个馆藏

Peach 支持同时挂载多个来源：本地硬盘、SMB 共享、经 CloudDrive2 挂载的网盘目录，以及不落本地盘的网盘媒体库（官方列出 PikPak）。扫描按只读处理，原始文件不动；整理、移动和删除需要使用者明确给可写挂载。

### 2. 元数据刮削：认编号，也认 NFO

识别不止靠文件名。影片编号、目录名、已有的 NFO 文件都是候选证据，命中之后从多个来源补标题、演员、厂牌和封面。

这里有个容易忽略的设计：刮削只填空白字段，不覆盖手工改过的内容。这条在文档里是写成架构决策的（ADR-0033、ADR-0165），不是「尽量不要覆盖」的口头承诺。对已经整理过一部分库的人来说，这个边界比刮得多不多更重要。

### 3. 海报墙与播放

封面墙可以拖拽浏览，点开原地播放，同一部片子的多版本和分卷归到一组。播放器带字幕加载、倍速、画面旋转、续播和时间轴预览，也可以交给外部播放器。

![Peach 数据流示意](/GitBoy/images/peach-local-media-library-review/02-flow.jpg)

### 4. 关注与追新

关注创作者之后，多个站点的更新会聚合进同一张卡片；按观看记录和收藏形成的口味偏好用于推荐，暂时不看的条目收进「想要」清单。

### 5. 云下载与自动入库

按编号搜索或粘贴磁力链接，交给网盘离线完成，落地后自动整理进馆藏。这是它和纯刮削工具的区别：从「找到」到「入库」是一条链路，不用在几个客户端之间来回倒手。

### 6. 馆藏治理与任务中心

标签、疑似重复、同一片子的多版本与分卷都能管理；支持按演员批量删除影片而保留资料和照片。后台任务在任务中心里可暂停、继续、取消，并显示 CPU、GPU 与下载占用。

## 二、适合哪些使用场景

- **本地已经攒了一批片子：** 文件名混乱、重复多、找不到，靠文件夹管不住。
- **NAS 用户：** 想把本地盘和网盘放进同一个界面，而不是两台设备两套目录。
- **在意数据留在自己手里：** 元数据和观看记录存在本机 SQLite，不依赖云端账号。
- **已有一份 NFO 元数据：** 不想被刮削器整体覆盖掉。
- **愿意折腾部署：** 能接受 Docker、端口、目录权限这些事。

如果只有几十个文件，或者只想双击打开就播，系统自带文件管理加一个播放器就够了，装这套反而多一层维护。

## 三、优点与注意事项

**优点**

1. 本地优先。账本就是一个本机 SQLite 文件，元数据、观看记录和口味数据都不上传。
2. 只补空白字段，扫描不改原文件，删除必须显式授权可写挂载——对存量收藏的破坏性低。
3. 平台覆盖完整：Windows 安装包与便携版、macOS 双架构 DMG、Docker 与 NAS 容器面板、源码运行。
4. 工程规范比同类项目严格得多：170 余条架构决策记录，变更日志强制中英对照并附来源编号，发布资产带 `SHA256SUMS.txt` 与 ed25519 签名。
5. 文档密度高。运维、来源配置、SMB、Docker、诊断、外部播放器各有独立页面，出问题有据可查。

**需要留意**

1. **还没到稳定期。** 最新版 `v0.60.0` 于 11 月 20 日发布，全部 release 仍标为 pre-release，仓库里 195 个 open issue。版本号推进快，说明功能也还在动。
2. **桌面包未签名，macOS 未公证。** Windows SmartScreen 会拦，macOS 会被 Gatekeeper 挡住，需要手动放行。安装前至少核对发布页的校验和。
3. **主力开发集中在一人。** 首位贡献者七千余次提交，其余多为两位数。项目活跃，但单点风险客观存在。
4. **遥测默认开启。** 安装器和设置页有一个「发送版本统计与错误诊断（推荐）」开关，**默认勾选**，内容是本机程序版本、系统版本、CPU 与内存档位这类技术字段，可以取消。上传馆藏与观看明细是另一个独立开关，默认关闭。
5. **源码运行门槛偏高。** 需要 Git、`uv` 和 Python 3.14 以上，3.14 目前还算新。
6. **体积不小。** Windows 完整安装包 238MB，打包了 FFmpeg、untrunc、人脸模型等媒体工具；macOS 的 DMG 在 270MB 到 300MB 之间。
7. **合规自己把握。** 项目面向成年人的私人收藏，README 明确说明不提供影片资源、也不提供付费内容入口。云下载、磁力提交这类功能涉及版权和站点服务条款，怎么用、用到什么程度，责任在使用者。
8. **数据要备份。** Docker 部署时配置、数据库和缓存都在 `/data` 卷里，重建容器不能删这个卷；0.60.0 专门加了 SQLite 损坏检测和停止写入的逻辑，说明数据损坏是真实发生过的故障。

## 四、安装方式

### Windows

到 Releases 页下载 `Peach-<版本>-windows-x64-setup.exe`（完整包）或 `windows-x64.zip`（便携版），后者解压即用。另有体积更小的 lite 安装包，媒体工具在首次使用时下载。

### macOS

下载 `macos-arm64.dmg` 或 `macos-x86_64.dmg`，拖进「应用程序」。包没有公证，首次打开会被拦，需要在「系统设置 → 隐私与安全性」里放行，或右键打开。

### Docker / NAS

在 `compose.yaml` 同目录建一个 `.env`，写上媒体目录和 NAS 的局域网地址：

```bash
PEACH_MEDIA_ROOT=/volume1/video
PEACH_BIND=192.168.1.10
```

然后启动：

```bash
docker compose up -d
```

浏览器打开 `http://<NAS 地址>:8900`，首次访问时设置密码。容器默认以 `1000:1000` 运行，NAS 目录属于别的 UID 时要显式设置 `PEACH_UID` 和 `PEACH_GID`。装完可以跑一次自检：

```bash
docker compose exec peach peach doctor
```

### 从源码运行（macOS）

```bash
git clone https://github.com/peach-mitao/peach.git peach-app
cd peach-app
uv sync --locked --python 3.14 --extra macos
./.venv/bin/peach-tray
```

托盘启动后会在浏览器里打开首次设置页。

## 五、综合评价

Peach 处理的是收藏变大之后才出现的那类问题：文件都还在，但已经不成体系。它的做法是把识别、刮削、入库、播放、追新这几步收进一个本机服务，用 SQLite 做账本，元数据留在自己机器上，用浏览器访问。

真正的取舍在元数据归属上。多数同类工具把刮削结果当成权威，改一次库就要赌一次；Peach 把「只补空白、不覆盖手改」写进架构决策，扫描默认不动原文件，删除要单独授权。这条路对已有收藏更友好，代价是初次整理要多花点时间确认字段。

短板同样清楚：版本号还在 0.x，全部发布都是 pre-release，桌面制品不签名不公证，主力开发一个人。用它的前提是能接受这些——愿意照文档部署、会核对校验和、数据库有备份。

**一句话评价：** 一个把本地影片收藏做成可检索馆藏的开源方案，元数据自主、链路完整，但仍在快速迭代期，适合愿意自己维护的技术型用户。
