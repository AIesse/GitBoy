![流畅阅读把英文网页逐段译成中文，原文与译文并排](/GitBoy/images/fluentread-bilingual-browser-extension-review/01-fluentread-bilingual.webp)

看英文网页这件事，最难的不是查词。词都认识，句子也读得下来，问题在于读到第三段就忘了第一段在讲什么——因为你的注意力被反复切走了：查一个词、回滚两行、重新找地方。真正有效的办法老得不能再老：一段原文，一段译文，并排放着，眼睛自己会对照。

**流畅阅读（FluentRead）是一个开源的浏览器扩展，把这件事做成了一键操作：在网页里逐段插入译文，原文不动，译文紧贴在下面。** 它同时提供划词翻译、AI 阅读理解卡片、图片与 PDF 文档翻译、YouTube 与 X 的双语字幕，许可为 GPL-3.0，全部功能免费，项目从 2024 年 1 月开发至今一直开源。

> 本文依据 FluentRead 官方 GitHub 仓库、官方文档站、Releases 发布说明与扩展截图整理，核对时间为 2026-11-23，属于资料型使用评价，不是逐项实机测试。星标、许可、版本号均以官方仓库与发布页为准；涉及运行时表现的描述，凡未亲自跑过的都会注明出处。

## 一、核心功能

### 1. 网页双语对照

安装扩展、打开任意外文网页、点一下弹窗里的「翻译页面」，页面就会在原地变成双语版：每个段落下面多一行译文，标题、列表、引用都跟着走。再点一次恢复原文，不刷新、不重载。

这套做法的好处是保留了原文的排版和信息密度，坏处也很直接——页面长度翻倍，长文要滚更久。官方对此的处理是给了一个「仅译文」的切换，以及针对单个网站的自动翻译规则：常看的站点设成进页面就自动译，不必每次点。

![划词后弹出 AI 阅读理解卡片，可切换读懂、拆句、用法、练习](/GitBoy/images/fluentread-bilingual-browser-extension-review/02-fluentread-reading-card.webp)

### 2. 划词与 AI 阅读卡片

选中一段文字，出现的不只是一个释义。官方把这张浮层叫「阅读卡片」，里面分了四个标签：

- **读懂**：先给这句话的整体意思，再点出语气与倾向。截图里那句 "A little curiosity goes a long way." 的解释是「一点好奇心，也能带来很大收获。语气轻松，带着鼓励」，而不是逐词硬译。
- **拆句**：把句子拆成结构，讲清主干和修饰关系。
- **用法**：把值得记的表达单独拎出来，给出中文对应和例句，比如 "go a long way" 配一句 "A little patience goes a long way."。
- **练习**：基于这句话生成练习题。

卡片底部有输入框，可以接着追问，它会把上下文一起带上。收藏的词句进「学习中心」，按原文语境存着，供之后复习。这类功能需要自己配置一个可用的 AI 服务；不配也能用翻译，只是没有讲解。

### 3. 图片、圈选与文档

网页里的图片文字也能翻：点图片翻译，或者用圈选工具框一块屏幕区域，识别出文字后给译文，译文可复制。官方说明用的是本地 PaddleOCR 做识别，0.0.42 版还允许手动指定用 CPU（WASM）跑，不再完全依赖后台自动判断。

文档翻译是另一条独立入口，支持 PDF、ePub、DOCX 等格式。打开后左侧是文件信息和翻译设置，右侧是阅读区，可以在原文、双语、译文三种视图间切换，也能进「校订译文」逐句改，改完下载回文件。扫描版 PDF 会走 OCR，识别出来的文字可以选中复制，官方的提醒也很实在——不确定的数字要对着原件核一遍。

![文档翻译：左侧设置与进度，右侧原文与双语视图切换](/GitBoy/images/fluentread-bilingual-browser-extension-review/04-fluentread-document.webp)

### 4. 视频双语字幕

YouTube 和 X 的视频可以显示双语字幕，支持只显示原文、只显示译文、双语并列三种模式。部分 X 视频还能用本地模型做语音转写生成字幕，模型可复用同一个本地目录，已下好的 Whisper 模型能从旧位置迁过来。0.0.42 版把原生字幕时间轴扩到了 Bilibili、Udemy（含 Business）和 edX，也支持页面里嵌入的 YouTube 播放器。

看技术演讲、看发布会录播，这一条比翻译整页更实用——视频没法「先通读一遍再回头看」，字幕是唯一能边看边对照的位置。

### 5. 翻译服务：免费优先，可换可自备

![翻译服务设置：免费翻译服务为默认，按顺序自动切换多条线路](/GitBoy/images/fluentread-bilingual-browser-extension-review/03-fluentread-services.webp)

设置里的「翻译服务」分两块：「我的服务」最多加 20 个自定义配置；「机器翻译」预置了 9 项，包括 MyMemory、微软翻译、谷歌翻译、DeepL、DeepL X、小牛翻译、有道翻译等。

默认选中的是「免费翻译服务」，行为是**按设置顺序自动切换可用线路**：主线路超时、限流或被拒，就往下走一条，失败的服务会被暂时跳过。截图里能看到这个列表允许拖动排序、单独开关，也能「检查连接」。

需要更高质量的场合，可以接 DeepL 的正式 API，或者接 AI 服务、本地 Ollama 模型。前者要自己的密钥，后者要本机有算力——官方把选择权交给你，没有默认强制走某一家的付费通道。

## 二、适合哪些使用场景？

- **每天要读英文信息源**：技术文档、GitHub issue、Hacker News、外媒报道，想读原文又不想频繁切窗口。
- **在学语言，需要「同一句话两种说法」**：双语并排是最省事的对照教材，配阅读卡片的拆句和用法，比查词典学得快。
- **要处理 PDF 论文和报告**：arXiv、PubMed Central 这类站点官方还做了专门入口，能直接进双语模式，保留目录、公式和引用。
- **看外文视频**：讲座、发布会、教程，需要字幕而不是整页翻译。
- **讨厌账号与订阅**：不想为了翻译网页注册第三个账号，也不想每月付一次钱。
- **对隐私有要求**：文档在本地解析，只有文字被发到所选服务；阅读记录存在本机 30 天，随时能清。

反过来说，这些情况它帮不上：Safari 用户（官方安装渠道是 Chrome、Edge、Firefox 和油猴脚本，没有 Safari 版本）；需要企业级术语一致性和审计的场景；以及指望「装上就零配置好用」的人——免费线路能用，但稳定性不属于你控制。

## 三、优点与注意事项

**优点**

- **开源且免费**：GPL-3.0，全部功能开放，没有「高级版」门槛。近两年时间一直保持这个姿态，官方 README 里写得很直白。
- **双语对照是主路径，不是附属功能**：默认行为就是逐段插入译文，而不是弹一个译文侧栏让人左右横跳。
- **翻译线路可替换**：9 项机器翻译加自定义服务，免费线路还能自动 fallback，不会一条挂了就整个不能用。
- **功能覆盖面罕见**：网页、划词、图片、圈选、文档、视频字幕六件事塞进一个扩展，而且每件都不是玩具级。
- **维护活跃、社区真实**：截至 2026-11-23，仓库 1.11 万 star、645 fork、40 位贡献者，最近一次提交在 2026-11-22，最新版本 v0.0.42 于 2026-11-15 发布，更新节奏基本一周一版。
- **更新说明写得像人话**：每个版本的 release note 分中英两段，逐条列改了什么、修了什么，不是一句 "bug fixes and improvements"。

**注意事项**

- **免费线路是非官方接口。** 设置页自己标明了「微软翻译 非官方公开 API」「谷歌翻译 网页接口」「DeepL X 免费非官方」，这些线路随时可能被上游掐掉或限流。它做了自动切换和失败冷却，但这是打补丁，不是保证。
- **AI 讲解要自备服务。** 阅读卡片的读懂、拆句、用法、练习全依赖 AI 服务，不配就只能拿到机器翻译。免费 AI 别指望稳定，官方也把「第三方服务的费用与可用性由服务商决定」写在明面上。
- **双语排版会撑长页面。** 复杂站点（重前端、瀑布流、动态加载）插入译文后偶有错位，官方在版本说明里反复在修这类问题，说明它是个持续战场。
- **文档翻译依赖本地算力。** 扫描件走 PaddleOCR，大文件在弱机器上会卡；译文只留在当前页面，不下载就走会丢。
- **项目体量决定了维护风险。** 67 个 open issue、主要靠个人投入、赞助商目前只有一家（B 站 Index-Translate）。这不是唱衰，而是选工具时该知道的事实：它现在很好用，但它不是一个有商业公司在后面兜底的产品的替代品。
- **与「沉浸式翻译」定位重叠。** 两者都是双语对照 + 划词 + 文档，选择时看你更在意开源许可、还是更在意商业支持的稳定度。这个判断我没法替你下。

## 四、安装方式

### 1. 从扩展商店装（推荐）

官方给了四个渠道，装完刷新页面即可：

- Chrome 应用商店：`djnlaiohfaaifbibleebjggkghlmcpcj`
- Edge 加载项：`kakgmllfpjldjhcnkghpplmlbnmcoflp`
- Firefox 附加组件：搜索「流畅阅读」
- 油猴脚本：Greasy Fork 上的同名脚本，只提供核心网页翻译能力

各商店的版本更新有时间差，想追新版就盯 Releases 页。

### 2. 三步用起来

1. 装完扩展，刷新要翻译的网页。
2. 点扩展图标，选目标语言。源语言默认自动检测，也能手动指定。
3. 点「翻译页面」。划词翻译、悬浮翻译、图片翻译这些要到设置里单独打开。

### 3. 配置翻译服务（可选）

默认的「免费翻译服务」开箱即用。要质量就进设置 → 翻译服务 → 我的服务 → 添加，填 DeepL 密钥或 AI 服务的地址与模型。凭据只存在当前设备，设置会随改随存。

### 4. 从源码跑

```bash
git clone https://github.com/FluentRead/FluentRead.git
cd FluentRead
pnpm install --frozen-lockfile
pnpm dev
```

Node.js 版本按 `.nvmrc`，包管理器按 `package.json` 的 `packageManager` 字段来，两处都写死了版本，别自己猜。

## 五、综合评价

翻译插件这个品类已经被做烂了，多数产品的思路是「给你一个更聪明的译文」——用更好的模型、更顺的语序，让你忘了自己在读外语。流畅阅读走的是另一条：它不假装翻译不存在，把原文和译文摆在一起，让你自己看差别在哪。这在一部分人看来是退步，在另一部分人看来才是学习该有的样子。

它真正值钱的地方是对「非官方接口」这件事的坦白。设置页直接把每条线路的性质标出来，哪条是网页接口、哪条要密钥、哪条随时可能挂，一眼看得见。比那种把不稳定藏在「智能引擎」四个字背后的产品诚实得多。

代价也清楚：免费线路是别人的接口，AI 讲解要你自己接服务，扫描件要靠本机 CPU 硬扛，项目体量还撑不起企业级的稳定性承诺。它适合愿意花十分钟配一下、然后长期白嫖一个顺手工具的人；不适合需要「保证能用」四个字的人。

**一句话评价：** 一个把双语对照做扎实的开源扩展，功能密度远超预期，免费线路的稳定性是它唯一没法替你担保的部分。
