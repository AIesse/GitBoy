处理 PDF 这件事，多数人的流程是零碎的：合并用一个小网站、压缩用另一个、加水印再换一个、扫描件要 OCR 又得找第四个。每换一个网站就要上传一次文件，合同、发票、证件扫描件这种东西一旦传出去，就再也收不回来了。

**Stirling PDF** 是一套开源的 PDF 处理平台。它的思路很直接：把合并、拆分、压缩、转换、OCR、签名、脱敏、加水印这些散落在各个网站上的功能收进一个界面，整套程序跑在你自己的机器上——可以是桌面应用，也可以是浏览器打开的本地服务，文件从头到尾不经过第三方。

它的代码仓库在 GitHub 上有 9.7 万 star，最新稳定版 v3.4.0 发布于 2026 年 11 月 19 日，官方在自己的宣传图上写的是「3000 万+ 下载、免费开源」。

![官方宣传图：3000 万+ 下载、免费开源](/GitBoy/images/stirling-pdf-open-source-pdf-toolkit-review/02-og.jpg)

> 本文依据 Stirling PDF 官方 GitHub 仓库、README、发布说明与官方界面截图整理（2026-11-21），属于资料型使用评价，并非对全部工具逐项实机测试。功能状态以官方仓库与文档为准。

## 一、核心功能

### 1. 五十多个工具，全在右侧一个面板里

打开界面，结构很朴素：左边是文件库，中间是工作区，右边是一整列工具。工具按用途分组，截图里能看到的是这几组：

- **推荐**：PDF 文本编辑、合并、比较、压缩、格式转换、OCR 扫描件清理、脱敏、多功能合一；
- **签名**：证书签名、时间戳、手写签名、共享签署；
- **文档安全**：加密、水印、盖章、清理隐藏信息、扁平化、解锁表单、修改权限；
- **验证**：读取 PDF 全部信息、校验数字签名；
- **文档审阅**：修改元数据、编辑目录。

官方 README 的说法是「50+ PDF 工具」，界面支持 40 多种语言，这一点对国内用户比较实用——不用在英文界面里找按钮。

![工具按用途分组：推荐、签名、文档安全、验证、文档审阅](/GitBoy/images/stirling-pdf-open-source-pdf-toolkit-review/04-tools.jpg)

### 2. 文本编辑直接搬进了查看器

v3.4.0 这一版的重点更新就是 PDF 文本编辑器，而且改成了「边看边改」：在查看器里点一下顶部的编辑文字按钮，就能直接改内容，不用先跳到另一个页面。

配套还修了两个实际痛点。一是字体，它现在能调用服务器上的字体，包括放在 `customFiles/static/fonts/` 里的自定义字体；处理扫描件（OCR 过的文档）时，它会尽量把文字匹配回原文档的字体，还给了个新的字体选择器。二是文件体积，保存时内嵌字体会做子集化，只嵌入实际用到的字形，不会因为改了一行字就把整份字体塞进去。

### 3. 扫描件：OCR、压缩和清理

纸质文件扫描出来的 PDF 本质是一堆图片，不能搜索、不能复制、体积还大。Stirling 对应的工具是 OCR 扫描件清理（OCR / Cleanup scans），识别之后文字变得可选中、可搜索。

压缩工具用来瘦身，格式转换支持 PDF 与图片、Office 文档之间的互转。这一组基本覆盖了「收到一份扫描件，想把它变成能用的文档」的全过程。

### 4. 签名、脱敏与文档安全

对经常处理合同的人来说，这组工具是最有价值的。签名支持用证书签，也支持时间戳和手写签名；脱敏（Redact）是真的把内容从文件里抹掉，不是画个黑框盖住——这两者差别很大，后者在 PDF 里往往还能被还原。

文档安全组里的清理隐藏信息（Sanitize）和扁平化（Flatten）也是同一类思路：把批注、表单、脚本、元数据这些「看得见看不见」的残留清干净再对外发送。

v3.4.0 还加了两件相关的事：一个是签名检测界面，另一个是管理员可以禁止用户编辑文档从而让已有签名失效——后者明显是给企业场景准备的。

### 5. 三种形态：桌面端、网页端、私有 API

同一套程序能用三种方式跑，这一点在开源 PDF 工具里不常见：

![三种用法：桌面客户端、浏览器 Web UI、自托管加私有 API，共用同一套处理引擎](/GitBoy/images/stirling-pdf-open-source-pdf-toolkit-review/03-forms.jpg)

- **桌面客户端**：Release 页面直接提供 macOS universal 的 dmg、Windows 的 x86_64 msi 与 arm64 安装包、Linux 的 AppImage / deb / rpm。装完就能用，不需要 Docker。
- **浏览器 Web UI**：部署在自己机器或 NAS 上，浏览器打开，默认 8080 端口。
- **自托管 + 私有 API**：官方说几乎所有工具都有对应的 REST 接口，可以接进自己的系统做批处理，也能多人共用一个实例。

## 二、适合哪些使用场景？

- **经常处理合同、发票、证明材料：** 合并、拆页、加水印、加密码这些动作高频，又不想把文件传到陌生网站。
- **纸质材料要电子化：** 扫描件做 OCR 之后可搜索、可复制，归档才有意义。
- **对文件外发有顾虑：** 医疗、法务、财务类文档，跑在本机或内网是最省心的合规姿势。
- **需要批量处理：** 几百上千份文件统一加水印、压缩或转格式，用 API 比手工点界面靠谱。
- **团队共用一台机器：** 部署在部门服务器上，同事用浏览器访问，省得每人装一堆小软件。

反过来说，如果一个月只合并两三次 PDF，直接用系统自带的预览或任意在线工具成本更低，没必要为此维护一个服务。

## 三、优点与注意事项

**优点**

- 工具覆盖面广，从日常合并压缩到签名、脱敏、无障碍检查都有，不用在多个网站之间来回搬文件。
- 三种部署形态任选，桌面版对完全不想碰命令行的人很友好。
- 界面 40 多种语言，中文完整可用。
- 有 REST API，能程序化调用，这是多数在线 PDF 工具给不了的。
- 版本迭代很快，2026 年基本保持每月一到两次发版。

**注意事项**

- **它是 open-core，不是整仓单一开源许可。** 主仓库是 MIT，但 `app/proprietary/`、`app/saas/`、`engine/`、`frontend/src/editor/proprietary/` 这些目录另有各自的许可证。商用前建议把 LICENSE 读完，别只看一个 MIT 就下结论。
- **部分功能属于付费档。** 官方有 Pro 与 Enterprise 两个档位，比如 OneDrive 支持在 Pro 计划里，SCIM 2.0 用户同步属于 Enterprise。核心的 PDF 处理工具是免费的，但「企业级」那几项不是。
- **Docker 镜像体积不小。** 拉取时如果网络一般，第一次会比较慢；官方同时提供 JAR 包和桌面安装包，可以绕开 Docker。
- **服务端部署要考虑资源占用。** 大文件转换、OCR 都吃 CPU 和内存，放在低配 NAS 上处理几十兆的扫描件会比较慢。
- **桌面版与服务器版是两个安装包。** 想要「同事也能访问」，还是得部署服务器版，桌面客户端只服务本机。

## 四、安装方式

### Docker（服务器 / NAS，最常用）

```bash
docker run -p 8080:8080 \
  docker.stirlingpdf.com/stirlingtools/stirling-pdf
```

启动后浏览器打开 `http://localhost:8080` 即可。要挂载目录、改端口、加登录认证，官方文档里有更完整的 compose 写法。

### 桌面客户端

去 GitHub Releases 页面下载对应平台的安装包：macOS 用 universal 的 dmg，Windows 用 x86_64 的 msi 或 arm64 的 setup，Linux 用 AppImage / deb / rpm。装完直接打开，不需要额外配置。

### 从 JAR 运行

Release 里同时提供 `Stirling-PDF.jar`，适合已经有 Java 环境、又不想装 Docker 的情况；带登录的版本是 `Stirling-PDF-with-login.jar`。

安装细节以官方文档 **docs.stirlingpdf.com** 为准，版本之间命令和参数会有变化。

## 五、综合评价

Stirling PDF 解决的是一个很具体的问题：**把 PDF 处理从「到处找网站」变成「打开一个自己的工具」**。它不追求功能上的独门绝技，赢在齐、全、能自己掌控——这一点对每天跟文档打交道的人价值很大。

需要看清的是它的商业化边界。核心工具免费开源，但 OneDrive 集成、SCIM 这类企业能力在付费档；许可也不是简单的 MIT，而是 open-core。个人和小团队用免费部分完全够，公司采购前得对着 LICENSE 和定价页确认一遍。

如果你只是想找个能把扫描件 OCR 一下、把几份合同合并起来的工具，并且不想再把文件传给别人的服务器，它是我目前会推荐的第一个选择。

**一句话评价：** 一款把 PDF 处理全流程收进自家机器的开源平台，免费部分够用、边界也清楚，适合文档处理高频的人常驻。
