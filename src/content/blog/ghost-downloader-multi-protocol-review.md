![Ghost Downloader 3 官方 banner：任务窗口堆叠与吉祥物](/GitBoy/images/ghost-downloader-multi-protocol-review/01-banner.jpg)

浏览器自带的下载器，问题永远是那几个：单线程、断线不续、链接一过期就得从头再来。于是多数人的硬盘里最后会住进三四个工具——一个多线程下载器对付大文件，一个命令行工具抓 m3u8，一个 BT 客户端下种子，遇到 403 再翻出另一个「能过验证」的。工具越多，剪贴板越乱，任务列表也越难对齐。

**Ghost Downloader 3（下称 GD）是一个用 Python 与 Qt 编写的跨平台开源下载管理器，把 HTTP/HTTPS、FTP/FTPS、磁力与 BitTorrent、HLS/DASH 直播流、eD2k 这几类下载收进同一个任务队列**，外面再套一层浏览器接管、媒体嗅探与任务编辑。项目由 XiaoYouChR 维护，仓库建于 2023 年 8 月，采用 GPL-3.0 许可，界面提供 Windows、macOS、Linux、Android 四个平台的原生版本。

> 本文依据 Ghost Downloader 官方 GitHub 仓库、官方文档站 gd.xychr.com 与 v4.6 发布说明整理，属于资料型评价：功能、参数、版本号与限制均以官方文档为准。我没有在四个平台上逐一跑完整的下载流程，凡涉及速度与效果的结论都会注明来源是「官方文档写明」还是「官方实测记录」。

![Ghost Downloader 3 的模块关系示意：入口、处理、落盘三层，依据官方文档整理](/GitBoy/images/ghost-downloader-multi-protocol-review/05-structure.jpg)

## 一、核心功能

### 1. 分块调度：下载中不合并临时文件

多数多线程下载器的做法是把文件切成若干段并行拉取，收尾时再把分片拼回去。GD 的不同之处写在 README 的第一条功能里：「智能分块无需合并文件，自动适配带宽」。省掉合并这一步，既少一次整文件的读写，也不会因为合并失败留下一个残缺的临时文件。

官方文档对这套调度的补充是：新建任务时可以指定线程数，下载中还能通过「右键 → 编辑」随时增减，改动立即生效；速度不够时程序会自动增加线程。HTTP 任务的进度条按分片着色，每一段对应一个下载线程，所以进度条上的锯齿就是实时的线程分布。断点续传是标配——暂停后继续、退出程序后重启，都从上次的位置往下走，而不是重头下载。

![Ghost Downloader 3 主窗口的任务列表，三条任务分别是 HLS、种子与多文件下载](/GitBoy/images/ghost-downloader-multi-protocol-review/02-task-list.jpg)

### 2. 浏览器接管：把「另存为」换成完整的下载器

GD 的浏览器扩展有三种装法：一键安装（Chrome、Brave 等 Chromium 系，随桌面端更新）、商店安装（Chrome、Edge、Firefox，更新取决于商店审核周期）、导出 CRX（受限环境手动装）。装完还要配对，自动配对是在扩展面板点「自动配对」、桌面端弹窗点允许；自动配对不弹窗时，改用手动令牌，桌面端「设置 → 浏览器扩展」里复制令牌填进扩展即可。令牌可以重新生成，生成后旧扩展立即断开。

配对之后，浏览器里点下载链接会被扩展拦下来，交给 GD 弹出一个确认窗口（官方叫 Draft 模式）。这个窗口不是摆设：文件名可以直接改，URL、请求头、代理、线程数都能在开始下载前调整；下载路径、勾选的文件也能在这里定。

![添加任务时的确认窗口：从页面解析出的标题、缩略图、总大小与线程数滑块](/GitBoy/images/ghost-downloader-multi-protocol-review/03-add-task.jpg)

视频的处理更细一层。鼠标悬停在正在播放的视频上，会出现一个下载按钮，可以拖到别处、也可以关掉；点开扩展图标的「资源」列表，则能看到当前页面发出的所有媒体请求，多种画质会作为独立条目分别列出。对于音视频分轨传输的站点（高清视频常见），选中一条视频轨和一条音频轨就能走「合并下载」，桌面端分别拉取后自动合并。YouTube 和 Bilibili 会整体交给桌面端处理，支持画质选择、字幕（导出 `.vtt`，与视频同目录）与播放列表勾选，B 站还支持多 P。

有一个容易踩的坑官方专门写了：DRM 加密的视频（优酷、腾讯视频、爱奇艺等）能看到请求，但下下来放不了；需要登录的内容要用视频上的下载按钮触发，因为按钮会带上当前登录状态，而从资源列表手动复制链接不会。

### 3. 协议与功能包：一个程序顶掉几个

GD 的协议清单是它最有竞争力的地方：HTTP/HTTPS、FTP/FTPS（链接指向目录时会列出文件树供勾选）、磁力与 BitTorrent（`.torrent` 可拖入窗口或导入，多文件种子能勾选需要的文件，下载中也能改勾选）、HLS/DASH（`.m3u8`、`.mpd` 粘贴即认，可录直播）、eD2k。

BT 侧的细节是完整的：下载完成后自动做种，分享率上限与时间上限在「设置 → BitTorrent」里配；暂停或退出后重启，从上次位置继续。

直播录制值得单独说。粘贴直播的 m3u8/mpd 链接后，GD 会识别为直播流，确认窗口里可选分辨率、可设录制时长上限（留空为不限），录制中的任务卡片显示已录制时长和速度。加密流会自动解密，对应开关「设置 → M3U8 下载 → MP4 实时解密」默认开启。但直播录制不支持暂停——停止即结束，无法接续，输出格式是 `.ts`，要 MP4 得自己转。录制功能依赖 N_m3u8DL-RE 与 ffmpeg，首次使用要在设置里装运行时（Android 版已内置）。

eD2k 走的也是外部运行时：首次使用前需在「设置 → 综合下载设置」里安装对应运行时，再在「设置 → 关联设置」注册 `ed2k://` 协议（关联设置仅 Windows 和 Linux 可用）。

这些能力并非全部塞在主程序里。GD 采用「功能包」结构，v4.6 的发布说明列出了随版本更新的四个包：`m3u8_pack` 1.3.3、`bittorrent_pack` 1.4.2、`yt_dlp_pack` 1.4.2、`bili_pack` 1.4.3。功能包可以脱离主程序单独推送更新，这也是为什么同一个版本号下，HLS 解析或 B 站接口的修复能先到你的机器上。此外 README 提到内置了 GitHub 与 HuggingFace 的镜像加速，对经常拉 Release 附件或模型权重的人来说省事。

### 4. 网络层：TLS 指纹模拟与代理

下载被 403 挡住，多数时候不是链接的问题，而是对方在比对 TLS 握手的特征——普通下载器的指纹和真实浏览器差距明显。GD 的做法是模拟真实浏览器的网络特征，官方文档给出了四档设置：自动（默认，来自扩展的任务匹配来源浏览器，手动添加的用 Chrome 最新版）、不模拟、指定浏览器（Chrome/Edge/Firefox/Safari 并可指定版本）、按域名切换（「设置 → 身份预设」，支持 `*.example.com` 通配，按列表顺序匹配，可拖动调优先级）。

与之配套的是请求头编辑：表格视图逐行改，或者文本视图直接粘贴一整条 cURL 命令。文档提醒了一个细节——开启指纹模拟时，手动设置的 User-Agent 不会生效，要完全自定义请求头必须先把指纹设为「不模拟」。

代理支持 `http`、`https`、`socks4`、`socks5` 四种写法，都可以在 URL 里带用户名密码，留空则不走代理；按域名指定代理同样通过身份预设完成，命中预设的下载不走全局代理。代理只影响下载流量，扩展与桌面端之间的连接不经过它。

### 5. 自动化：aria2 RPC、ghd 命令行、计划任务

GD 内置了一个 Aria2 RPC 兼容服务，默认端口 16800。开启后，支持 Aria2 RPC 的工具（文档举的例子是 LinkSwift）可以直接把任务推过来，不需要另外装 aria2。需要清楚它的边界：只实现了 `aria2.addUri`（支持 `out`、`dir`、`header`、`user-agent`、`referer`）和 `aria2.getVersion`，其余方法没有；服务只监听 `127.0.0.1`，不能跨机器调用；也不能通过 RPC 暂停、删除或查询任务状态。换言之，它是一个「接任务的入口」，不是完整的 aria2 替代品。

命令行则走另一条路：在「设置 → 命令行工具」里安装 `ghd` 之后，可以在终端里探测链接、添加任务、等待完成。

计划任务解决的是「下完就走」的场景：点工具栏的时钟图标，设定所有任务完成后关机、重启、休眠或打开指定文件，触发条件是所有正在运行和等待中的任务全部结束。配合「下载分类」——按扩展名匹配、可给每类指定独立目录（支持 `{default}/视频` 这样的占位符，图标 25 种可选）——基本能把「下完之后文件散落一地」的问题处理掉。

## 二、适合哪些使用场景？

- **经常从官网、网盘、Release 页拉大文件**：需要多线程、断点续传，还要在浏览器里点一下就直接进下载器，而不是让浏览器自己慢慢拖。
- **要下视频但不想装一堆命令行工具**：HLS/DASH、分轨合并、字幕、播放列表勾选都在图形界面里完成，不用记 yt-dlp 的参数。
- **偶尔用 BT，不想为它单独装一个客户端**：磁力、种子、文件勾选、做种上限都在同一个程序里。
- **追直播、需要留档**：m3u8/mpd 直播流可以直接录，能设时长上限，加密流自动解密。
- **已经在用 aria2 生态**：想给 Aria2 RPC 找一个带界面的执行端，或者让 LinkSwift 这类工具把任务推过来。
- **多平台混用**：Windows 台式机、macOS 笔记本、Linux 小主机、Android 手机，希望四端操作逻辑一致。

不适合的场景也很明确：需要下载 DRM 保护的流媒体（优酷、腾讯视频、爱奇艺这类），或者需要跨机器远程管理下载队列（RPC 只监听本机、方法也不全）。

## 三、优点与注意事项

优点：

- **协议覆盖广**：HTTP、FTP、BT/磁力、HLS/DASH、eD2k 一套程序全包，省掉在几个工具之间搬链接的麻烦。
- **开源且活跃**：GPL-3.0，仓库 18,226 star、1,086 fork，v4.6 于 2026 年 11 月 25 日发布，同日仍有代码提交；功能包还能独立推送修复。
- **分块设计省事**：下载中不合并临时文件，少了整文件复制的开销，也少了合并失败的风险。
- **任务参数可改**：下载中能改 URL、文件名、目录、线程、代理、请求头，改 URL 时内容一致则保留进度，不一致才提示重下。
- **界面是原生的、不是网页壳**：四端共用一套 Qt 界面逻辑，Windows 安装版与便携版可选，便携模式只需在 exe 同级建一个空的 `GhostDownloader` 文件夹。

注意事项：

- **系统门槛不低**：Windows 需 10 以上，macOS 需 13.0 以上，Linux 需 glibc 2.35 以上；不支持 Windows 7，也不支持没有 AVX 指令集的 CPU（官方说法是 2011 年以前的处理器）。
- **Android 版是裁剪版**：不含 BitTorrent，也不支持 eD2k，ed2k 关联设置只在 Windows 与 Linux 可用。
- **直播录制不可暂停**：停止即结束、无法接续，输出为 `.ts`，要 MP4 需自己转；网络中断超过一定时间会导致录制缺失片段。
- **DRM 内容抓不到**：官方实测表里优酷、腾讯视频两站 GD 均为不支持，这不是配置问题。
- **aria2 RPC 只是最小实现**：只有 `addUri` 与 `getVersion`，仅本机访问，无法通过 RPC 管理任务状态。
- **Linux 打包方式变了**：v4.6 起不再提供 `.deb`，改用安装脚本、AppImage 或 `.tar.xz`，习惯 apt 装包的人需要换方式。
- **官方性能数据要打折看**：文档里的实测记录标注为「单次测量，一台机器，一条家用宽带」，版本是 GD 4.2.2 对 IDM 6.43、Motrix Next 3.9.6、Gopeed 1.9.3，且 OneDrive 那一行 GD 与 Motrix Next 用了 128 连接、IDM 与 Gopeed 是 32，条件并不对等。它能说明趋势，不能当成普适结论。
- **文档有一处自相矛盾**：BT 的代理支持，功能页写「仅 SOCKS5 对下载流量生效」，代理页的表格却把 HTTP、SOCKS4、SOCKS5 都标为支持。实际以你所用版本的设置为准。

## 四、安装方式

### Windows（10 以上，x86_64 / arm64）

从 GitHub Releases 下载对应架构的安装包：`*-Setup.exe` 会写进 Program Files 并创建快捷方式，`*.zip` 是便携版，解压即用、不改注册表。想强制便携模式，在 exe 同级目录建一个空的 `GhostDownloader` 文件夹即可；运行中也可以在「设置 → 应用 → 数据存储模式」切换安装版与便携版的数据位置。

### macOS（13.0 以上，Intel / Apple Silicon）

下载 `.dmg`，按常规方式拖进 Applications。安装包里附带的说明就是「把 Ghost Downloader 拖动到 Application 文件夹，即可完成安装」。

### Linux（glibc 2.35 以上）

v4.6 提供 AppImage 与 `.tar.xz`，另有一键安装脚本；Arch 用户可以用社区维护的 `ghost-downloader-bin` 或 `ghost-downloader-git`。从 v4.6 起官方不再发布 `.deb`，Debian/Ubuntu 用户请改用 AppImage 或安装脚本。Linux 端支持应用内更新，AppImage 除外。

### Android（9.0 以上，arm64-v8a）

直接安装 `Ghost-Downloader-v4.6-Android-arm64-v8a.apk`，支持增量更新与后台下载，可录制直播，但不含 BT 与 eD2k。

![Android 端官方截图：左侧为任务列表与分片进度，右侧为直播录制中的任务](/GitBoy/images/ghost-downloader-multi-protocol-review/04-android.jpg)

### 命令行工具 ghd

在「设置 → 命令行工具」里安装 `ghd`，之后可以在脚本里调度任务：

```sh
# 只看种子里有哪些文件，不添加任务
ghd probe "https://example.com/a.torrent"

# 只下第 0、3 个文件，落到 ./downloads
ghd add "https://example.com/a.torrent" --select 0,3 -o ./downloads

# 列出任务、查看详情、等待结束
ghd tasks
ghd task tsk_0123
ghd wait tsk_0123
```

常用子命令还有 `pause`、`start`、`remove`（移除任务并删除未完成的文件）。配合计划任务，可以在 `ghd wait` 之后让机器自动休眠。

官方项目地址：[github.com/XiaoYouChR/Ghost-Downloader-3](https://github.com/XiaoYouChR/Ghost-Downloader-3)

## 五、综合评价

GD 的思路不是「做一个更快的下载器」，而是「把分散在几个工具里的下载能力收进一个队列」。所以它的功能列表很长，从多线程 HTTP 一直到 eD2k 和直播录制，但每一项都没有做到极端：RPC 只实现两个方法，直播录制不能暂停，DRM 内容明确不支持。这是一种取舍——用广度换掉一部分深度，代价是遇到专业场景时你还是得回到专用工具。

它真正的优势在几个交叉点上。第一是浏览器到桌面端的链路做得完整：拦截、Draft 确认、画质与字幕选择、分轨合并、登录态携带，这些环节都能在同一个窗口里完成。第二是任务可编辑，下载到一半发现线程给少了、代理没走对、指纹被拦了，右键改完继续，不用推倒重来。第三是工程上愿意解决问题而不是绕开问题：TLS 指纹模拟是为了应付反爬，功能包拆分是为了让 HLS、B 站这类接口变化能单独修。这三件事凑在一起，才让「一个程序顶几个」这句话站得住。

需要清醒的地方同样清楚：它要求较新的系统和 CPU，Android 版砍掉了 BT 与 eD2k，Linux 的打包方式刚经历变化，官方性能数据是自测且单次。把它当成主力下载器是合理的，把它当成唯一工具则会碰到边界。

**一句话评价：** 用广度换取便利的开源下载器，把 HTTP、BT、HLS、eD2k 和浏览器接管收进一个队列，代价是每个专项都留了一点「还需要专用工具」的余地。
